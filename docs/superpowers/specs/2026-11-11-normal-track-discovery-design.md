# 정상 쪽 탐색 경로 추가 — 설계 (2026-11-11)

## 왜 하는가

1차 판정 모델의 가장 큰 문제는 정상 게임·결제 화면을 도박으로 잘못 잡는 것이다(15% 안팎, 목표 2%). 이걸 줄이고, 줄었는지 확인하려면 **본 적 없는 사이트의 헷갈리는 정상 화면**이 필요하다. 그런데 지금 야간 루프는 도박 쪽으로만 찾는다.

- 검색 키워드가 도박 단어뿐이다(`keywords.txt` 10개 + 자동 키워드).
- 커뮤니티 링크와 광고 배너도 도박 사이트로만 이어진다.
- 그래서 헷갈리는 정상은 29곳(198쪽)뿐이고, 그중 9곳은 합법 사행(도박으로 옮길 예정), 8곳은 놀이터 안전 기관이다. 실제 게임·결제 사이트는 서너 곳이다.

## 목표

- 야간 루프가 정상 쪽 키워드로도 후보를 찾아, 지금과 같은 절차(미리 찍기 → 사람이 판정 → 시드 반영)로 `hard_negative` 사이트를 늘린다.
- 도박 쪽 탐색의 동작과 품질은 바뀌지 않는다.

## 하지 않는 것

- 시험용 사이트를 날짜로 떼어 두는 것, 화면마다 정답을 확인하는 것, PC 폭 화면 처리, 돈 넣는 화면 수집 — 따로 다룬다.
- 자동 승격. 판정은 계속 사람이 한다.
- 차단·접속 확인 화면 우회, 로그인, 결제.
- 정상 쪽 키워드의 자동 확장(정상 사이트 제목에서 단어를 뽑아 키워드를 늘리는 것). 처음에는 손으로 정한 키워드만 쓴다.

| C. 정상 쪽 전용 명령·후보 파일 | 완전 분리 | 같은 코드를 두 벌 관리하게 된다 |

## 정한 것

### 1. 키워드 파일

`seeds/keywords_normal.txt`. 형식은 `keywords.txt` 와 같다(한 줄에 하나, `#` 주석). 처음 넣을 15개:

| 종류 | 키워드 |
|---|---|
| 게임 결제 | 게임 캐시 충전 · 게임 아이템 상점 · 모바일 게임 쿠폰 |
| 상품권·간편결제 | 문화상품권 충전 · 포인트 충전소 · 기프트카드 구매 |
| 스포츠 | 프로야구 경기 결과 · 축구 실시간 스코어 · e스포츠 중계 |
| 금융 | 코인 거래소 · 주식 시세 · 환율 계산 |
| 경품·이벤트 | 룰렛 이벤트 · 출석체크 이벤트 · 경품 응모 |

복권·토토·경마 같은 합법 사행 키워드는 넣지 않는다(판정 대상을 도박 화면 전부로 넓히기로 했으므로 정상이 아니다).

### 2. 검색 단계

- 정상 키워드는 밤마다 `nightly_search_normal`(기본 5)개만 돌린다. 가장 오래 안 돌린 것부터 고른다(자동 키워드와 같은 회전 방식, `explore_state.json` 에 origin `normal` 로 기록).
- 순서는 도박 키워드(수동 + 자동) 다음이다. 검색 엔진의 접속 확인에 걸려 중단되더라도 도박 쪽이 먼저 끝나 있게 한다.
- 정상 키워드로 찾은 후보의 출처는 `search-normal:<키워드>` 다. 도박 쪽은 지금처럼 `search:<키워드>`.
- 정상 키워드는 결과가 0이어도 퇴역시키지 않는다(손으로 정한 목록이다).
- 수동 실행: `crawler discover search --keywords seeds/keywords_normal.txt --track normal`. `--track` 기본값은 지금 동작(`gambling`)이다.

### 3. 후보 선택(미리 찍기)

- 밤당 전체 상한은 지금처럼 `nightly_max_candidates`(40)이다. 판정 부담을 늘리지 않는다.
- 그 안에서 정상 쪽은 최대 `nightly_max_normal_candidates`(기본 15)곳, 도박 쪽은 나머지(40 − 뽑힌 정상 수)다.
- 각 쪽 안에서는 지금처럼 `added_at` 최신순, 같은 등록 도메인은 첫 행만.
- 정상 쪽 후보가 15곳보다 적으면 남는 자리는 도박 쪽이 쓴다. 반대는 하지 않는다(도박 후보가 적어도 정상은 15곳까지만).

### 4. 자동 키워드 확장

- 미리 찍은 후보 중 출처가 `search-normal:` 인 것의 제목은 자동 키워드 추출에 넣지 않는다.
- 본 데이터셋 쪽은 지금도 `gambling` 라벨 제목만 쓰므로 바뀌지 않는다.

### 5. 판정표의 추천

- 색인 행의 `seed_source` 가 `search-normal:` 로 시작하면 신호에 `normal_track` 을 넣는다.
- 추천 순서: `normal_track` 이 없으면 지금 규칙 그대로. 있으면 차단 → 커뮤니티 → 주소 신호(`ref_param`·`tld_gambling`·`idn`·`numeric`) 2개 이상이면 `gambling` → 그 밖에는 `hard_negative`.
- 즉 정상 후보에는 `deposit_page`·`menu_terms` 규칙을 적용하지 않는다(충전 화면은 정상 쪽에서 일부러 찾는 화면이다).
- `review.csv` 의 칸 구성은 바꾸지 않는다(신호 칸에 `normal_track` 이 보인다).
- (11/11 실행 뒤 수정) 처음에는 도박 규칙을 모두 먼저 봤는데, 정상 충전 사이트 15곳 중 10곳이 충전 화면 신호 때문에 gambling 으로 추천돼서 바꿨다.

### 6. 보고서

- 밤 보고서(`report.md`)와 `--dry-run` 계획에 정상 키워드 수, 정상 쪽으로 추가된 후보 수, 미리 찍은 정상 후보 수를 따로 보여 준다.

### 7. 종류 정보

- 어느 키워드로 찾았는지는 `candidates.csv` 의 출처와, 승격 뒤 본 색인 행의 `seed_source` 에 남는다. 승격 때 시드 파일의 출처는 지금처럼 `review:<날짜>` 다. 종류별 집계는 나중에 색인의 `seed_source` 로 한다.

## 만드는 사람에게 맡기는 것

- 함수와 인자를 어떻게 나눌지(예: `select_candidates` 에 인자를 더할지 함수를 나눌지).
- `SearchTally` 를 도박·정상에 따로 둘지 하나로 쓸지. 단, 정상 쪽의 결과 0 연속이 도박 쪽 중단 판단에 영향을 주면 안 된다.
- 보고서 문구.

## 시험

- 정상 키워드 회전: 가장 오래 안 돌린 것부터 n개.
- 검색: `--track normal` 이면 출처가 `search-normal:` 로 기록된다. 기본은 `search:`.
- 후보 선택: 정상 20·도박 50이면 15 + 25, 정상 3·도박 50이면 3 + 37, 정상 20·도박 10이면 15 + 10.
- 신호·추천: `normal_track` 만 있으면 `hard_negative`, 주소 신호가 2개 이상이면 `gambling`, 충전 화면·메뉴 신호만 있으면 `hard_negative`, 차단이면 `blocked`.
- 자동 키워드: 정상 쪽 후보 제목은 추출 대상에 없다.
- 기존 시험 115개는 그대로 통과한다.

## 다 됐는지 확인하는 방법

1. `crawler nightly --dry-run` 출력에 정상 키워드와 후보 자리가 보인다.
2. `crawler nightly --only search,explore` 를 한 번 실제로 돌려 `review.csv` 에 `normal_track` 후보가 나오고, `keywords_auto.txt` 에 정상 쪽 단어가 들어가지 않았는지 본다.
