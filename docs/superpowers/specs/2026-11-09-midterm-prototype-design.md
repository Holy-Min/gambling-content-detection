## 7. 결정된 방법

### 7.1 G1 판정 모델

- **입력 화면**: 각 ok 페이지 PNG의 **첫 화면**(상단 824×1830px = 폰 한 화면). 사용자가 실제로 마주치는 화면이고, 온디바이스 판정도 현재 화면 단위이기 때문(내 결정). 전체 페이지 아래쪽은 쓰지 않는다. 이미지 높이가 1830보다 작으면 있는 만큼.
- **라벨**: 양성 = `gambling`, 음성 = `hard_negative` + `normal`. `embedded_banner`(웹툰·무료 중계 사이트 화면에 도박 배너가 박힌 화면)는 학습에서 빼고 **별도 분석**으로 "최종 모델(전체 데이터로 학습)이 이 화면을 도박으로 판정한 비율"만 보고하며 지표 2에 넣지 않는다. 해석은 합격/불합격이 아니라 **열린 설계 질문**으로 쓴다: 멈칫 1차 범위는 도박 사이트 화면 판정이므로, 배너 화면에서 약속 카드가 뜨는 것이 "조기 경고"인지 "과잉 개입"인지는 실제 사용자 테스트(12~13주차)에서 정할 질문으로 넘긴다(내 결정).
- **충전 화면 재현율(지표 3)**: `gambling` 중 `page_kind == "deposit"`(40쪽)이 도박으로 판정된 비율. 휴리스틱 라벨임을 명시.
- **목표치(10/7 문제정의서 §2.4, `/Users/seongmin/Documents/대학원/AI활용현업문제해결/[양식 4] 문제정의서_김성민.docx`)**: 지표 1 융합 F1 ≥ 0.90 · 지표 2 정상 게임·정상 결제 화면 오탐률 ≤ 2%(계획은 하드 네거티브 500장, 현재 138쪽) · 지표 3 충전 직전 화면 재현율 ≥ 0.90 · 지표 4 융합이 단독 대비 F1 +0.03 이상. 보고서는 "목표 대비 1차 결과"로 달성/미달을 그대로 적는다.
- **평가 단위**: 지표는 **화면(쪽) 단위**로 계산하고(온디바이스 판정이 화면 단위이므로), 표본 수는 항상 "화면 n쪽 / 도메인 m개"로 같이 적는다. 도메인별 다수결 같은 도메인 단위 지표는 내지 않는다(내 결정).
- **평가 분할**: 라벨 비율을 맞춘 도메인 단위 StratifiedGroupKFold(k=5). 음성 풀은 hard_negative 25 + normal 8 = 33개 도메인이라 fold마다 음성 도메인이 6~7개 들어간다(normal만 보면 fold당 1~2개 — 그래서 normal을 따로 층화하지 않는다). 모든 지표는 **out-of-fold 예측**을 모아 계산한다(각 화면은 자기 도메인을 한 번도 보지 않은 모델이 판정). 같은 분할을 3모델에 공통 적용. 시드 고정.
- **불확실성**: 도메인 단위 부트스트랩(1,000회) 95% 신뢰구간을 F1·오탐률·재현율에 붙인다. 표본이 작아 구간이 넓을 것이며, 넓은 그대로 보고하고 "1차 결과·표본 확대 필요"로 해석한다(내 결정).
- **지표 2의 분모**: hard_negative 화면만(정상 게임·결제·합법 토토 등). normal(일반 화면) 오탐률은 별도 행으로 보고한다.
- **임계값**: 0.5 고정(검증셋 튜닝 없음 — 표본이 작아 과적합 방지). 참고로 오탐률 2%를 맞추는 임계값에서의 재현율도 함께 보고.
- **OCR**: Apple Vision `VNRecognizeTextRequest`(accurate, 언어 `ko-KR`,`en-US`, 언어 보정 켬)를 Swift CLI로 호출. 결과(줄 텍스트·신뢰도·박스)를 화면 id별 JSON으로 캐시. 캐시는 저장소 밖 `~/datasets/gambling/_features/ocr/`(사이트 문구가 들어 있으므로).
- **텍스트 모델**: 글자 n-gram(2~4, `char_wb`) TF-IDF + 로지스틱 회귀(`class_weight="balanced"`). 공백·대소문자 정규화.
- **이미지 모델**: CLIP ViT-B/32 이미지 임베딩 + 로지스틱 회귀. 세로로 긴 첫 화면은 정사각에 가까운 타일 2장(위·아래)으로 잘라 각각 임베딩 후 평균(가운데만 잘리는 것 방지 — 내 결정). 임베딩도 `_features/`에 캐시.
- **융합**: 텍스트·이미지 확률의 단순 평균(가중치 0.5/0.5). 스태킹은 하지 않는다(표본 작음).
- **판정 근거(약속 카드용)**: 양성 판정 화면마다 로지스틱 회귀 기여도(계수×TF-IDF)가 큰 n-gram을 포함한 OCR 줄에서 뽑은 **키워드 3개 이내**. 시안에는 사이트 고유 문구·도메인을 지우고 일반화한 키워드(예: "첫충", "입금", "배당")만 쓴다.
- **오류 분석**: 오탐(하드 네거티브·일반을 도박으로) 전부, 미탐(도박을 놓침) 상위 10건을 도메인 해시·화면 종류·OCR 글자 수·추정 원인으로 표로 정리(이미지 없이). 원인 범주 예: OCR 글자 거의 없음(이미지형 화면), 로그인 모달만 보임, 합법 토토·게임 결제 문구 유사.
- **처리 시간**: 맥에서 화면 1장당 OCR·임베딩·분류 시간 중앙값(참고치, 온디바이스 아님).
- **코드 위치**: `src/detector/`(패키지) + `scripts/vision_ocr.swift`. 분할 누수 검사·지표 계산·부트스트랩은 테스트를 먼저 쓴다(pytest). 새 의존성: scikit-learn, CLIP 로더(transformers 또는 open_clip 중 빌더 선택) — `requirements` 분리(`requirements-detector.txt`).
- **산출물(공개 가능분)**: `docs/week11/metrics.json`, `docs/week11/metrics.md`(3모델 비교표·신뢰구간·표본 수), 혼동행렬·3모델 막대그래프 PNG, `docs/week11/error_analysis.md`(이미지·원문 없음). 화면 원본·OCR 원문은 저장소 밖.

### 7.3 G2 클릭 시안

- `prototype/web/index.html` 단일 파일, 외부 라이브러리·폰트 없음(시스템 한글 글꼴), 폰 프레임(412×915 비율).
- 흐름: ① **약속 켜기**(약속 문구, 기간 30/90/180일, 시작 금액 본인 입력, 개입 강도 3단계 — 알려만 주기 / 멈칫하기(기본) / 충전 화면 막기, 신뢰인 지정(선택)과 알림 범위) → ② **단톡방 새 주소**(가상의 메신저 화면, 링크 클릭) → 판정 중 → **약속 카드**(불법 도박 판정 + 판정 근거 키워드 칩 + 내 약속 + 끊은 지 N일·잃은 돈, [나가기] 기본, [계속 보기]는 60초 뒤) → ③ **충전 화면 → 30초 쿨다운**(지금까지 잃은 돈 + 이번 금액, [나가기] [신뢰인에게 알리기 — 보낼 내용 미리보기] [1336 익명 채팅], [계속]은 카운트 후) → ④ **나의 기록**(재접속·멈춤 횟수, 멈춘 금액).
- 강도별 동작: 알려만 주기 = 카드·쿨다운에서 바로 계속 가능 / 멈칫하기 = 60초·30초 지연 / 충전 화면 막기 = 쿨다운에 [계속] 없음. 끄기·강도 낮추기는 "24시간 뒤 적용" 안내.
- **정상 결제 통과 경로**: 모바일 게임 인앱결제 화면 → 개입 없음, 잘못 잡힌 경우 "정상 게임" 표시(기기 안 예외) 버튼.
- 도박 사이트·충전 화면은 **실제 캡처 대신 CSS로 그린 일반 목업**(공개 저장소이므로 — 내 결정).
- 데모 편의: 타이머 10배속 토글, 처음부터 다시.
- 문구는 쉬운 말(합니다체 아닌 앱 말투 해요체), "중독" 대신 행동 표현.
- 보고서용 스크린샷: 저장소 venv의 Playwright로 각 상태를 헤드리스 캡처 → `docs/week11/prototype/*.png`.

### 7.4 G3 AI 페르소나 사전 점검

- **페르소나 8개**(양식 4 §3.4 대상 구성을 따름, 전부 가상):
  - 경험 청소년 대리 3 — ⓐ 고1 남, 카지노형, 단톡방 새 주소로 재접속(문제정의서의 준혁) ⓑ 고2 남, 스포츠 베팅, 친구 추천 코드 ⓒ 중3 여, 소액 반복·상품권 충전
  - 회복자 2 — 청소년기에 시작해 지금 20대 초반(1명은 차단 앱을 지운 경험)
  - 상담사 2 — 1336 헬프라인 상담사, 학교 Wee클래스 상담교사
  - 신뢰인 1 — 경험 청소년의 보호자(부모)
- 페르소나마다 **별도 에이전트**(sonnet, 8개 동시 실행, 서로의 답을 보지 않음). 입력: 페르소나 카드, AS-IS 시나리오, 시안 스크린샷. 일정이 밀려도 8개를 유지한다(병렬이라 시간 차이가 작음 — 내 결정).
- **1회차**: 화면을 순서대로 보며 생각 말하기, 선택 기록(약속 카드 나가기/계속, 쿨다운 선택, 고를 강도와 이유, 15/30/60초 중 적당한 길이), 감시처럼 느껴지는 지점, 잃은 돈 합계 표시의 역효과 여부, "켜 두겠다/지우겠다"와 지우고 싶은 순간. 상담사·신뢰인은 "권할 수 있나, 어떤 조건이면".
- **2회차**: 내가 1회차 답을 읽고 페르소나별 꼬리 질문 2~3개(SendMessage로 같은 에이전트에 이어서). 대화 기록이 남게 한다(피드백 4).
- **편향 방지**: "앱을 칭찬할 필요 없다, 실제 그 사람처럼 거절·무관심도 가능"을 명시하고, 지우고 싶은 순간·짜증 나는 지점을 반드시 묻는다. LLM 페르소나는 동의 쪽으로 기우는 경향이 있으므로 결과는 **가설 생성용**으로만 쓴다.
- **내 검토 표**: 발견 → AI 반응 요약 → 내 판단(수용/보류/기각) → 이유 → 반영(시안 수정 / 실제 테스트 질문으로 이관). 수용한 것 1~3개는 시안에 반영하고 before/after 스크린샷을 남긴다.
- 산출물: `docs/week11/persona_test/`(페르소나 카드, 대화 전문, 요약·검토 표). 모든 파일 머리에 "AI 페르소나(합성 사용자) 사전 점검 — 실제 사용자 테스트 아님".

### 7.5 G5 보고서

- 양식 docx를 python-docx로 채운다(10/7 양식 4 때의 `build4.py` 방식). 스크립트·그림은 과목 폴더 `week11_images/`에. 작성 안내 상자와 각 장의 파란 안내문 상자는 삭제하고 내용으로 대체.
- 표지: 프로젝트명 「멈칫 — 화면으로 판정하는 청소년 도박 브레이크(화면 속 도박 콘텐츠 탐지)」, 작성일 2026. 11. 11., 수행자 김성민(학번 202650299, 충남대학교 바이오AI융합학과), 공동수행자 없음(행 삭제), 지도교수 김영국 교수, 현업 협력자 해당 없음, 주제 연계 유형 ■ 학위논문.
- 장별 핵심:
  - **요약**: 반 쪽, 고객(돈을 잃어본 청소년) → 두 순간 → 화면 판정 + 약속 카드·쿨다운 → 1차 수치 → 12/16 목표.
  - **1장**: 공감 단계 — 실제 청소년 인터뷰 미수행 사유(미성년 도박 경험자 모집은 보호자 동의·윤리 심의 필요, 1인 기간 한계) 적고 공백 + 대신 한 것(문헌·상담 통계, AI 페르소나 사전 점검은 4장). AS-IS(두 순간). 기존 해결책 한계. **리서치 문제 검증(G4 수치)**. AI가 필요한 이유(주소가 아니라 화면 내용으로 판정해야 함).
  - **2장**: 최종 정량 목표, 중간까지/최종까지 범위 표, 문제정의서 대비 변경(4클래스→이진 1차, 안드로이드 데모→웹 시안, 인터뷰→12~13주차)과 **피드백 반영 표**(피드백 1~6 → 반영 내용 / 미반영 사유).
  - **3장**: TO-BE vs AS-IS 흐름도(BPMN 스타일 그림), 시스템 구성도(폰 안: 캡처→OCR·이미지→융합→개입 / 기록은 기기 안 / 사람과 AI 역할), 데이터·모델·도구 표, **특강 적용**(클로드 기반 연구 자동화 = Claude Code로 수집기·야간 탐색 구현, 에이전틱 프로세스·BPMN = 야간 탐색 루프의 사람 승인 게이트, 다중 에이전트 = 페르소나 점검·구현/검증 에이전트 분리, 보안 가드레일 = 차단 우회 금지·robots.txt·도메인 해시·화면 비공개·외부 API 전송 금지, IXP·Data Fabric = 적용 계획).
  - **4장**: 프로토타입 범위(1차 판정 모델 + 클릭 시안), 시안 스크린샷, 3모델 비교표·혼동행렬, 오류 분석, AI 페르소나 사전 점검 결과(합성 표기)와 검토 표, AS-IS 대비 개선(페르소나 선택 기록 — 가설로 표기), 문제점과 개선 방향. 저장소 링크.
  - **5장**: 기대효과(정량은 목표치 기반, 정성), 학위논문 연계(한국어 모바일 도박 화면 데이터셋·융합 비교).
  - **6장**: 역할 표(수행자, 지도교수, AI 도구 — Claude Code(수집기·모델 코드·문서 초안), AI 페르소나 에이전트(사전 점검)) + **AI 결과물 피드백 표**(AI 산출 → 내가 지적한 점 → 바뀐 것). 실제 사례: AI가 자동 분류한 도박 후보에 커뮤니티가 섞임 → 사람 재검토로 이동·삭제 / 차단 사이트 우회 기능 제안 → 넣지 않기로 결정(우회 없이 기록만) / "기존 보안 앱에 탑재하면 설치 장벽이 없다"는 논리 → 반박 후 독립 앱 / 페르소나 점검 결과 검토(7.4).
  - **7장**: 남은 과제, 일정표(11/12~12/16 5칸), 위험·대응·필요 지원(실제 청소년 접근을 위한 기관 협조·윤리 심의 안내 등).
  - **8장**: 데이터 출처(공개 웹 화면 자동 수집, robots.txt 준수, 차단·봇 확인 우회 없음, 원본 비공개, 도메인 해시), 개인정보(화면에 개인정보 없음, 로그인 안 함), IRB(실제 사람 연구 미수행 — 진행 시 심의 필요 여부 확인 예정), 생성형 AI 도구·범위·검증 방법(AI 페르소나는 합성 데이터로 표기), 에이전트 가드레일.
